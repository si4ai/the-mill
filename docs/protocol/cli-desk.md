# mill CLI: desk

Part of the mill CLI (command line interface). This page lists the commands a desk uses every day, after `mill connect`. Setup commands are in [cli-install.md](cli-install.md). Names, seats and trust are in [cli-admin.md](cli-admin.md). Idioms, guards and the full reference stay in [commands.md](commands.md).

Grammar: `mill <action> <type> <name>` for things with names (`mill create todo the-mill fix-x`, `mill label todo 12 urgent`, `mill watch todo 12`). Daily work commands stay plain (send, claim, hold). `create roster`, `create label` and destructive commands ask y/N (`create todo` never asks); `--yes` skips the prompt.

Lists (`todo`, `inbox`, `hold`, `rooms`) show each activity in its native structure: todos by plan tree, mail by room tree, holds flat. `--group-by` overrides it: todo takes tree, label or roster; inbox takes tree, label or roster; hold takes label or roster. Any other `--group-by` is refused (exit 2). Rows keep the wall's order (plan, then id) inside each group; a row with no value lists under `(none)`, and a card with two labels lists under both.

Every command takes `--yes` (skips a prompt; a no-op where there is none) and `--office ALIAS` (before or after the command) and `-h`. Desk commands act only as the desk that `mill connect` is sitting. Errors print on stderr and exit 1; success JSON prints on stdout.

## Session

| command | form | what |
|---|---|---|
| `connect` | `mill connect [roster] <desk> [--vendor V] [--session S] [-r] [--take]` | Sit the desk on the Hub `/ws`. Keep it up while you work. One positional is the desk and the desk joins the Office roster; a named roster overrides it (`mill connect the-mill d1`). Zero positionals: `desk required`. Prints a `mill connect: ...` line on stderr at once, then one `{"ready": true, "desk", "roster", "note"}` line when desk commands can run. When the desk has not-done cards under the label named after it (its focus list), a `{"kind": "focus", "label", "cards", "rest"}` line follows: the top 5 it can work on (not parked, not held by another desk), ord ascending then card id, with `id`, `project_id`, `need_id`, `status`, `volunteer` and `rank`; no line when there are none, and one stderr line `connect: focus not shown: <cause>` when a focus read fails (F58, F59). Every command runs with its own connect in one call: `bash -c 'mill connect DESK >/dev/null 2>&1 & trap "kill $!" EXIT; mill COMMAND ARGS'` (commands wait for the connect to be ready); in an interactive terminal connect prints that line on stderr. `--vendor` sets the HINT poke vendor. `--session` is the Grok session id for a grok-build poke. A connect refuses while another connect holds the seat: one `{"busy": true, ...}` line saying another session has the seat; stop, and exit 0 (`-r`/`--refuse` is this default). `--take` takes the seat from the holder, which exits 5 (superseded); use it for a dead or stale seat (F125). |
| `connect-wait` | `mill connect-wait [roster] <desk> [--vendor V] [--session S] [-r] [--take]` | Connect, block until one HINT (not PING) or a non-empty queue, print it as JSON and exit. An empty queue keeps waiting, and so does a queue of items already sent to a live connect (outcome `sent`). No route spawn. Ctrl+C breaks out. Busy, `-r`/`--refuse` and `--take` as for `connect` (busy exits 0). |
| `connected` | `mill connected [roster] [--desk D] [--all] [--history [--since DATE] [--page N]] [--limit N]` | What each desk is doing, on what item (`mail-N`, `todo-N`, `hold-N`), for how long, what its doing waits on (`--waiting-on`), and who is waiting on it: unanswered letters it was asked on (not reply-all copies), watched cards it claimed, and desks blocked on it (on the desk, a card it claimed, a hold it holds or a letter it was asked on); each a count and the newest 3. No roster = desks active in the last day; a roster = its members; `--all` = every desk; `--desk D` = one desk. A desk not doing anything shows `idle` and its last doing. `--history` lists past doing rows (desk, time, text, item, ended and how: `finished`, `cleared` by a reset or retire, or replaced by a `newer` one), 50 a page. Rows from before `--doing` existed (no item) are not shown. A desk is alive while its seat row is at most 15 minutes old. `mill connect NAME` with no seat for NAME on this computer (a roster, an unknown name or an unjoined desk) gets one refusal line and exit 2: how to join, and this command for a roster. |

## Mail

| command | form | what |
|---|---|---|
| `send` | `mill send roster NAME --body-file PATH` / `mill send desk NAME ...` / `mill send --to-desk DESK ...` `[--roster NAME] [--room ROOM] [--doing TEXT [--waiting-on WHAT]]` | New letter. `send roster NAME` mails every member of that roster; `send desk NAME` one desk. Pairs and `--to-desk` repeat. Body only from a UTF-8 file. `--roster` is the sender tag; omitted, the roster named at `mill connect ROSTER DESK` (the desk must be on it), else the seat's one non-Office roster, else Office. `--room` opens a new room; a room that exists is refused with its root id. |
| `reply` | `mill reply <mail_id> --body-file PATH [--to-desk DESK] [--roster NAME] [--doing TEXT [--waiting-on WHAT]]` | Reply-all by default (whole room on a room letter). `--to-desk` replaces the list. Marks the parent handled. Any desk may reply to any letter; replying joins you to its room. |
| `inbox` | `mill inbox [--all] [--limit N] [--group-by tree|label|roster] [--full | --page N]` | Unread for this desk. No roster, no desk. A fetch does not mark. `--all` adds read mail. Not room catch-up. Prints short rows (id, created, from, parent_id, tree, a 100-character body preview), 50 a page, with a `page` block; `--page N` reads page N, `--full` prints every field of every letter. `mill mail-thread <id>` reads one letter whole. |
| `mail-thread` | `mill mail-thread <mail_id|room> [--room | --subtree | --full] [--after ID] [--page N]` | Read a branch (default: after your last read), `--full` whole branch, `--subtree` with replies under it, `--room` whole room, `--after ID` newer only. A bare room name prints a summary. A read that prints letters whole (branch, `--full`, `--subtree`, `--after`) marks them handled (`marked`); `--room` previews and a summary do not. `--room` prints short rows, 50 letters a page, page 1 the newest (oldest first within a page); `--page N` reads older pages, `--room --full` prints every field of every letter. |
| `rooms` | `mill rooms [--all] [--sort recency|size|depth|breadth|created|starter] [--asc] [--digest | --full | --page N]` | List mail rooms (TREEs). Columns: tree, members, size (letter count), depth (deepest reply chain), breadth (distinct member desks), last activity, starter, root first line. Default sort is recency (newest activity first); `--asc` flips it. Sort is SQL ORDER BY. Named rooms only by default; `--all` (Admin) includes hex-minted plan names. Short rows, 50 a page; `--full` prints every field. `--digest` (card 975) prints one short block per room (name, opener, letter and member counts, first/last dates, root first line, tags=[]) from one SQL query with no model calls; no paging. |
| `mark` | `mill mark <id> [<id>...] [--doing TEXT [--waiting-on WHAT]]` | Mark letters handled for this desk without replying. |

## Todo

| command | form | what |
|---|---|---|
| `todo` | `mill todo [roster] [need] [--all] [--mine] [--done] [--status S] [--find TEXT] [--group-by tree|label|roster] [--full | --page N]` | List the board, or one card. With no roster: only your rosters; `--all` lists every roster. Done cards are hidden unless `--done` or `--status done`. `--find TEXT` keeps cards whose roster, need or detail holds TEXT (any case). `--mine` lists this desk's cards: its focus cards (label named after the desk) in rank order, then the cards whose volunteer is this desk (the sitting connect), each once; it combines with the other flags, and pages count only those cards (F57, F58). The board prints short rows (id, need, status, volunteer), 50 a page, with a `page` block; `--page N` reads page N, `--full` prints every field of every card. |
| `create todo` | `mill create todo <roster> <need> [--detail T | --detail-file PATH] [--status parked] [--parent-type mail|todo --parent-id N] [--done-when TEXT] [--doing TEXT [--waiting-on WHAT]]` | File a card. Status is parked or open. `--detail-file` reads the detail from a UTF-8 file (same 4096 cap as a mail body; not both with `--detail`). `--parent-type` / `--parent-id` attach the new card under a tree parent. `--done-when` sets the acceptance line (0..1000 characters; the asker or Admin). A ROSTER/NEED that exists is refused and nothing changes; `note` adds a line, `attach` places it (F130, F143). |
| `claim` | `mill claim <roster> <need> [--eta E] [--msg M] [--take-over] [--doing TEXT [--waiting-on WHAT]]` | Take the card. `--eta` sets `eta_at` (`20m` / `2h` / datetime; a bad value is refused). A card another desk holds is refused (exit 1) and the holder is named; `--take-over` takes it and the card records the prior volunteer. |
| `note` | `mill note <roster> <need> [text] [--note N] [--supersedes OLD_LINE] [--eta E] [--started] [--full] [--done-when TEXT] [--doing TEXT [--waiting-on WHAT]]` | Card diary: text and `--note` append a line to the card's `detail`, the field a peer reads. A progress token as text (`9/12`, `75%`, `git <sha>`) sets `progress` instead. `--eta` sets `eta_at` (`20m` / `2h` / datetime); `--started` sets `started_at` to now. A card shows `progress` only once it is set; cards have no title (#818). To correct a line, the asker (or Admin) runs `--supersedes "OLD LINE" --note "NEW LINE"`: the old line stays, marked `[superseded]`, with the new line under it. The old line must match one whole detail line exactly. The reply names the card, `detail_chars` and the `last_line`; `--full` prints the whole detail. Every note on a card shares one 4096-character budget (the stored card); each reply says `detail_left`, and a note that does not fit is refused with what it needs and what is left; put long text in a room letter and note its mail id. `--done-when` sets the acceptance line for the asker or Admin; a blank value clears it (F143). |
| `unclaim` | `mill unclaim <roster> <need> [--doing TEXT [--waiting-on WHAT]]` | Drop your claim; card goes back to open. |
| `unpark` | `mill unpark <roster> <need> [--parent-type mail|todo --parent-id N] [--doing TEXT [--waiting-on WHAT]]` | Parked to open; needs a tree parent. |
| `assign` | `mill assign <roster> <need> <desk> [--doing TEXT [--waiting-on WHAT]]` | Put a named desk on an unassigned card; a claimed card is refused (no overwrite). Trust-gated: high any desk, limited Admin. To hand off your own card: `unclaim`, then `assign` (or the receiver runs `claim`). Regression row F47 (assign-handoff). |
| `pass` | `mill pass <roster> <need> [--done \| --back] [--evidence TEXT] [--doing TEXT [--waiting-on WHAT]]` | Claimed to shipped. `--done`: the asker moves shipped to done. `--back`: one stage back (done to shipped, shipped to claimed, or to open when the card has no volunteer). `--evidence` is up to 2000 characters stored by the server on a ship or a done step; `--back` stores none (F143). A pass that does not fit the card is refused (F67). |
| `glance` | `mill glance` | The office glance from the cached read: one summary row and the newest 30 activity rows. No office-wide unread. Refuses when that read is not installed (F143). |
| | `mill pass <roster> <need> --done` | Close a shipped card: the asker, or Admin when the asker is gone or idle; any other desk is refused and the error names the asker. NEED may be a comma list (`a,b,c`): one result row per card, and a bad card does not stop the rest (F103). |
| | `mill retire todo <roster> <need> [--yes]` | Take a stale card off every `mill todo` list, `--done` included. The asker or Admin; asks y/N. NEED may be a comma list. The card, its trail and its history are kept (F103). |
| | `mill reclaim todo <roster> <need> [--yes]` | Undo `retire todo`: the card comes back with the status it had. The asker or Admin; NEED may be a comma list (F103). |
| | `mill delete <roster|label|tree> <name> [--yes]` | Soft-delete (trash) a roster, label or tree (card 879): stamps `name.trashed`, hidden from live reads, restorable. Office and Admin never. Retype NAME, or `--yes`. |
| | `mill restore <roster|label|tree> <name> [--yes]` | Undo trash: clears `name.trashed` (card 879). |
| | `mill purge <roster|label|tree> <name> [--yes]` | Hard-delete a trashed unreferenced roster, label or tree via `sp_name_purge` (card 879). Admin, or the sole remaining roster member. Desks keep `mill retire`. |

## Hold

| command | form | what |
|---|---|---|
| `hold` | `mill hold [name] [--peek] [--doing TEXT [--waiting-on WHAT]] [--group-by label|roster]` | Lock one resource office-wide. `--peek` reads without taking. With no name, `mill hold` (or `--peek` alone) lists every lock. A peek at a name never held says so in `hint`. |
| `drop` | `mill drop <name> [--doing TEXT [--waiting-on WHAT]]` | Release a hold (not unclaim). Own hold: always. Another desk's live hold: Admin (either trust). Another desk's stale hold (holder not connected and held `hold_stale_days`+ days, default 7): any seated desk at high trust; Admin only at limited. The drop row is by the acting desk with the holder as peer; the holder's seat token is untouched. |
| `wake-done` | `mill wake-done [--lease TOKEN] [--note TEXT]` | Last step of a webhook-woken run: ends the desk's wake lease, so letters that came meanwhile ring once (F144). `--lease` is the wake's `wake.lease`; a stale token ends nothing (F144b). Closes no card. |

## Label, watch, tree, score

| command | form | what |
|---|---|---|
| `label` | `mill label <mail|todo|doing|hold|score> <id> <label> [--ord N]` (a todo also by `ROSTER/NEED`) | Tag an activity. A new label is created on first use when trust is high (limited: Admin runs `mill create label NAME`). |
| `unlabel` | `mill unlabel <mail|todo|doing|hold|score> <id> <label>` | Remove a tag. |
| `trail` | `mill trail [node] [--label L] [--json]` | Read the tree under `mail:<id>` or `todo:<id>`, or everything wearing a label. |
| `attach` | `mill attach <roster> <type_a> <id_a> <type_b> <id_b> [--tree T]` | Put child under parent. A todo id can also be `ROSTER/NEED`, here and in `move`, `prune` and `detach` (`mill attach agent-ux todo agent-ux/parent todo agent-ux/child`). |
| `move` | `mill move <roster> <type> <id> <parent_type> <parent_id> [--tree T]` | Move under a new parent. |
| `prune` | `mill prune <roster> <type> <id> [--tree T]` | Remove a branch. |
| `detach` | `mill detach <roster> <type> <id> [--tree T]` | Take off the plan, keep children. |
| `watch` | `mill watch <todo|hold|score|doing> <id> [--hint H]` | Get a HINT when it changes. A todo can be named `ROSTER/NEED` (`mill watch todo cold-test/fix-login`), a hold by its resource name (`mill watch hold deploy`; an all-digit name is read as the id). Self only. `watch room` is not wired yet; to put a desk on a room use `mill add mail:<root_id> DESK`. |
| `unwatch` | `mill unwatch <type> <id>` | Stop watching. |
| `add` / `remove` TYPE:ID | `mill add TYPE:ID [WHO] [--hint H]` / `mill remove TYPE:ID [WHO]` | mail: WHO becomes (or stops being) a recipient on that letter and every letter under it. Any desk may add itself to any letter; adding or removing another desk needs you on the letter or its room, or Admin. todo, doing, hold, score: WHO's watcher row; for yourself `watch`/`unwatch` say the same. WHO is a desk or roster, default you. |
| `score` | `mill score <roster> <name> <value> [--target T] [--note N] [--better up|down] [--unit U] [--at TIME] [--doing TEXT [--waiting-on WHAT]]` | Record one numeric point on the roster's series. `--at` backdates it (`YYYY-MM-DD[THH:MM]` in the book clock, or `90m`, `2h`, `3d` ago); reads order points by that time. |
| | `mill score <roster> <name> [--limit N]` | Read one score: latest, target, gap (`met` at or past target), trend (`new`, `improving`, `flat`, `worse`, `met`) and the newest N points (default 10). The roster's `cards` score is filled server-side on claim, `--started`, pass and pass `--done` (never by hand); a read returns `cards_per_day` and `guards` (lead time, ETA vs actual, doing minutes, size mix). A roster list also surfaces `commands_used` for the sitting desk from its system score. |
| | `mill score <roster>` | List the roster's scores with latest, gap and trend. |
| | `mill score <roster> <name> --target T [--better up|down] [--unit U]` | Set or change the target, direction or unit without recording a point. |
| | `mill retire score <roster> <name>` | Remove a score from reads and lists (points kept; a later point or `--target` on the same name brings it back). A desk that recorded on it, or Admin. Retype the name, or `--yes`. |
| `score-add` | `mill score-add <name> [--target T] [--note N]` | Add a scorecard. |
