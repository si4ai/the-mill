| F111 (validator-status-identity) | A forged `validator` status does not pass the queue. Anyone with write access (a PAT seat, a person, another workflow) can post a commit status with context `validator`; `validator_pass` counts only statuses whose creator login is exactly `si4ai-validator[bot]` (the si4ai-validator GitHub App, one named constant `VALIDATOR_LOGIN`) and whose creator type is `Bot` (`VALIDATOR_TYPE`, #663) and ignores every other creator, neither pass nor fail. It reads the full status list for the exact head sha (all pages, not the combined status, which keeps one status per context from any creator), and the latest counted status decides: success passes; failure, error, pending or none fails. A bot status on another sha, or under another context, does not count. On `pull_request` the check stays green (the PR must stay enqueue-able) but its line, `::notice` annotation and job summary start `WAITING:` or `REPORT:`, never a pass; the contract is in `docs/dev/CONTRIBUTING-PR.md` (#811). | `tools/check_validator_pass.py` `VALIDATOR_LOGIN`, `validator_state`, `pr_stage_line` | `tests/install/test_validator_status_identity_811.py` (all cases), `tests/install/test_validator_pass_810.py` (all cases) |
