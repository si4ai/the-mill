Every wake carries `wake.lease`, a 12-hex token per lease (null on the join test). `mill wake-done --lease TOKEN` (RPC field `lease`) ends only the lease that token names. A token that is not the current lease's is a stale done (a run that outlived `wake_lease_s` and says done after a newer wake): it keeps its note for the next wake unless a newer note waits, logs `wake=done stale=yes`, answers `stale`, and leaves the newer run's lease and held-back items alone. No token (a 0.7.18 client, or a routine that does not pass it) ends the current lease as in F144. The id on a POST is the one its own take stored, returned from that lock hold (`_new_lease`); `post_desk` never reads `_EPOCH` again, so a done or a newer take after the take cannot leave the POST with no id or a newer lease's id. | `wake._EPOCH` / `_new_lease` / `lease_done` / `wake_body` / `trail` / `gate_clear`, `rpc._h_wake_done`, `mill wake-done --lease` | `tests/server/test_wake_lease_races_887_888.py` (the token cases) |
