| F107 (uvicorn-proxy-trust-hardset) | mill-wall starts uvicorn with `proxy_headers` off and an empty `forwarded_allow_ips`, so `scope["client"]` is always the raw TCP peer. `FORWARDED_ALLOW_IPS` or `--forwarded-allow-ips` (`*`, the peer's address, a CIDR) cannot widen proxy trust: an untrusted peer that sends `X-Forwarded-For` with an allow-listed address or `127.0.0.1` still gets 403 at `door=ip` and at the human Wall ACL. `X-Forwarded-For` is read only by `allow.door_client`, and only from the proxies in `AGENT_COORD_TRUSTED_PROXIES` (default this host's loopback, the installed nginx edge). That setting is the only way to widen trust. Through the loopback edge the client is still the last hop that is not a proxy, never a forged leftmost entry: a public client behind the edge that puts an allow-listed address first still gets 403. A direct loopback connection still passes (#791). | `asgi.uvicorn_config`, `asgi.run_uvicorn` | `tests/server/test_uvicorn_proxy_trust_791.py` (all cases), `tests/server/test_door_ip_forwarded_651.py` |
