| F144 (wake-lease) | One woken run at a time per desk, server side (owner's 0.7.19 order; the Auditor desk's storm). A webhook POST takes a wake lease for that desk in the office's wall process. A connect sync does not end it (it used to clear the window on every sync, so a routine run's first per-call connect let the next letter POST again and start an overlapping cold run); it only resets the held-back count. While the lease is held, letters and hints wait in the push queue and post nothing (`wake=coalesced reason=lease`). `mill wake-done [--note TEXT]` (RPC `wake-done`, the caller's own seat only) ends it and logs `wake=done held_s=S queued=N note=yes|no`; when items were held back and rows still wait, exactly one trailing POST goes out with `wake.pending_count` (distinct items, a repeat counts once) and the note as `wake.last_note` (`reason=trailing`); a run that read every row sends none (`wake=none reason=drained`); a second done is a no-op. With no done (a crash, or a client older than the verb) the lease lapses after `wake_lease_s` (default 900 s): the lease-end timer sends the same one trailing POST (`reason=lease-expired`) and the next item after it POSTs at once, so no desk is wedged. Leases are per seat per office. F126 (a connected desk gets no wake) and F127 (room copies wake no one by default) are unchanged. No table or column.
