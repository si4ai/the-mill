| F123 (sync-rows-deleted-after-send) | A desk's push_queue rows are deleted only after the frame that carries them has been sent (#831). The connect sync and every command reply (ok or failed) read the rows without deleting them (`hold=True`, `rec_push.peek`), send the frame, then delete exactly those row ids (`ack_sync`). A frame that is never sent, because a newer connect kicked the socket (4000) or it closed, deletes nothing, so the next sync of that desk carries the rows. A row put after the read stays queued. No window leaves a row neither queued nor delivered; a frame sent just before a crash can come again and the chain dedupes it by poke key. | `asgi.ws_endpoint` (connect sync, reply loop), `asgi._ws_handle_client_text(acks)`, `asgi._ack_rows`, `push.take_sync(hold)` / `connect_sync_frame(hold)` / `sync_ids` / `ack_sync`, `records.push.peek` / `ack` | `tests/server/test_sync_batch_supersede.py` (all cases), `tests/server/test_sync_ack_831.py` (all cases) |
